### 지연 로딩

```java
@Entity
public class Member { 
    @Id
    @GeneratedValue
    private Long id;
			
    @Column(name = "USERNAME")
    private String name;
		
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "TEAM_ID")
    private Team team;
..
}
```

- `@ManyToOne(fetch = FetchType.LAZY)`
    - 지연 로딩
- `Member member = em.find(Membe.class, 1L);`
    - Member 만 가져옴, Team LAZY
- `Team team = member.getTeam();`
    - 프록시 객체
- `team.getName();`
    - 실제 team을 사용하는 시점에 초기화(DB 조회)
    - select team 쿼리

### 즉시 로딩

만약, Member과 Team을 함께 자주 사용한다면?

```java
@ManyToOne(fetch = FetchType.EAGER)
@JoinColumn(name = "TEAM_ID")
private Team team;
```

- `@ManyToOne(fetch = FetchType.EAGER)`
    - 즉시 로딩
- `Member member = em.find(Membe.class, 1L);`
    - Team을 `JOIN`해서 Member과 함께 가져옴

프록시와 즉시로딩 주의

- 가급적 지연 로딩만 사용
    - 즉시 로딩 적용시 예상하지 못한 SQL 발생
- **즉시 로딩은 JPQL에서 N+1 문제 일으킴**
- `@ManyToOne,` `@OneToOne` 기본이 즉시 로딩

  **⇒ Lazy로 설정**

- @OneToMany, @ManyToMany 기본이 지연 로딩

### JPA N+1 문제

상황

```java
@Entity
public class Member {
    @Id
    @GeneratedValue
    private Long id;
			
    @Column(name = "USERNAME")
    private String name;
		
    @ManyToOne(fetch = FetchType.EAGER) //기본값이 EAGER
    @JoinColumn(name = "TEAM_ID")
    private Team team;
	
}

@Entity
public class Team {
    @Id @GeneratedValue
    private Long id;
    private String name;
}
```

- 모든 회원 목록을 조회하고, 각 회원이 소속된 팀 이름도 출력해보자

```java
List<Member> members = em.createQuery("SELECT m FROM Member m", Member.class).getResultList();

for (Member member : members) {
    System.out.println(member.getTeam().getName()); // 각 팀 접근
}
```

- 가정 : 회원 3명, 각기 다른 팀에 속해있음

실제 발생하는 쿼리

- 먼저 `Member` 3명 조회 - 1번 쿼리

```sql
SELECT m.id, m.name, m.team_id FROM member m;
```

- 그리고 각 `Member` 의 `Team` 을 조회하는 쿼리가 3번 추가로 발생
    - 팀이 3명이면 3번

```sql
-- member1.getTeam()
SELECT t.id, t.name FROM team t WHERE t.id = 1;

-- member2.getTeam()
SELECT t.id, t.name FROM team t WHERE t.id = 2;

-- member3.getTeam()
SELECT t.id, t.name FROM team t WHERE t.id = 3;
```

- 총 1 + N(3) = 4번의 쿼리 발생 ⇒ N+1 문제

### 해결방법

**fetch join + Lazy Loading 사용**

```java
List<Member> members = em.createQuery(
    "SELECT m FROM Member m JOIN FETCH m.team", Member.class).getResultList();
```

→ 실행되는 쿼리 1번

```sql
SELECT m.id, m.name, t.id, t.name
FROM member m
JOIN team t ON m.team_id = t.id;
```

- 한 번에 모든 `Member`와 관련된 `Team` 정보를 조인해서 가져오기 떄문에 추가 쿼리가 발생하지 않음


> 💡
> **Fetch Join과 일반 Join의 차이**
> 
> - Fetch Join
>     - ORM에서의 사용을 전제로 DB Schema를 Entity로 자동 변환 + **영속성 컨텍스트로 영속화 해줌**
>     - `Fetch Join`을 통해 조회시, 연관 관계는 영속성 컨텍스트 1차캐시에 저장 → 다시 엔티티 그래프 탐색해도 조회 쿼리 수행X
> - 일반 Join
>     - 단순휘 데이터를 조회하는 개념
>     - 영속성 컨텍스트나 Entity와는 무관

> 💡Collection 연관관계 Fetch Join시 주의사항 <br>
> 예제 <br>
> 1:N 관계 (Collection 연관관계)
> ```java
> @Entity
> public class Team {
>     @Id @GeneratedValue
>     private Long id;
> 
>     private String name;
> 
>     @OneToMany(mappedBy = "team")
>     private List<Member> members;
> }
> ```
> 
> ```sql
> SELECT t FROM Team t JOIN FETCH t.members
> ```
> 
> - 이 쿼리는 Team 하나당 Member 수 만큼 결과 행이 생김
>     - 결과 중복 + JPA가 이를 중복 제거하면서 메모리에 다 올림
> 
> **데이터 중복**
> 
> - Teamd이 2개, 각 팀에 멤버 3명씩 있으면
>     - 총 6행 반환 (`TeamA + m1`, `TeamA + m2`, ... `TeamB + m3`)
>     - Team 중복되지만 JPA 영속성 컨텍스트로 중복 제거해줌
>     - 데이터 많아지면 메모리 터짐
> 
> **페이징 안 됨**
> 
> - JPA가 예외 던짐
>     - `HHH000104: firstResult/maxResults specified with collection fetch; applying in memory!`
>     - DB에서 페이징 불가능하고, 전부 다 메모리로 로딩 후 자바에서 페이징 ⇒ 성능 최악
> 
> - 1:N에는 Fetch Join 지양하고 N:1만 Fetch Join 사용
> - 1:N에는 Batch Size + 지연 로딩 사용
>     - `spring.jpa.properties.hibernate.default_batch_fetch_size: 100`
>     - 또는, 컬럼에 `@BatchSize(size = 100)`
>     - IN 쿼리로 최적화 해줌

**@EntityGraph (Spring Data JPA)**

```java
@EntityGraph(attributePaths = "team")
List<Member> findAll();
```

- 내부적으로 `fetch join`으로 동작 → 팀까지 한번에 가져오므로 N+1 문제 해결

**@BatchSize(지연 로딩 유지하면서 최소화)**

```java
@BatchSize(size = 100)
@ManyToOne(fetch = FetchType.LAZY)
private Team team;
```

- 여러 Team ID를 IN 절로 한 번에 불러오는 방식
    - ex. `WHERE id IN (1, 2, 3)`
