### 기본 값 타입

JPA에서 데이터 타입 → 엔티티 타입, 값 타입

- 엔티티 타입
    - @Entity 로 정의된 객체
    - **식별자(ID)가 있어** 데이터를 지속적으로 추적 가능
    - 변경되더라도 ID가 유지되므로 동일한 엔티티로 인식
    - ex. Member, Order
- 값 타입
    - int, double, String 같은 단순한 값
    - **식별자가 없고** 변경시 추적 불가능
    - 엔티티의 생명주기에 의존 , 엔티티가 삭제되면 값도 함께 삭제
    - ex. 주소(Address), 근무 기간(Period)
- 값 타입 분류
    1. 기본 값 타입 : int, Integer, String
    2. 임베디드 타입(복합 값 타입) : 여러 값 타입을 묶어서 사용  - @Embeddable
    3. 컬렉션 값 타입 : 값 타입을 컬렉션으로 저장 - @ElementCollection

### 임베디드 타입(복합 값 타입)

임베디드 타입이란?

- JPA에서 새로운 값 타입을 직접 정의할 수 있음
- **여러 개의 기본 값 타입을 하나의 객체로 묶어 사용**
- `@Embeddable` + `@Embedded` 를 사용하여 선언
    - `@Embeddable` : 값 타입을 정의하는 곳에 표시
    - `@Embedded` : 값 타입을 사용하는 곳에 표시
- 기본 생성자 필수
- 임베디드 타입의 값이 null 이면 매핑한 컬럼 값 모두 null

```java
@Embeddable
public class Address {
    private String city;
    private String street;
    private String zipcode;
}

@Entity
public class Member {
    @Id @GeneratedValue
    private Long id;

    private String name;

    @Embedded  // 임베디드 값 타입 사용
    private Address homeAddress;
}
```

| id | name | home_address_city | home_address_street | home_address_zipcode |
| --- | --- | --- | --- | --- |
| 1 | 철수 | Seoul | Gangnam | 12345 |
| 2 | 영희 | Busan | Haeundae | 54321 |

```java
//커스터마이즈 가능
@Embedded
@AttributeOverrides({
    @AttributeOverride(name = "city", column = @Column(name = "home_city")),
    @AttributeOverride(name = "street", column = @Column(name = "home_street")),
    @AttributeOverride(name = "zipcode", column = @Column(name = "home_zipcode"))
})
private Address homeAddress;
```

- `@AttributeOverrides` , `@AttributeOverride` 를 사용해서 컬럼명 재정의

장점

- 재사용 가능
- 응집력 증가 - 관련 필드를 하나의 객체로 묶어 고나리
- 엔티티를 더 세밀하게 설계 가능

### 값 타입과 불변 객체

- 값 타입은 불변(immutable) 객체로 만들어야 안전
    - `private final String city;`
    - 생성자로만 값 설정
- 값 타입을 여러 엔티티에서 공유시 부작용(size effect) 발생 가능

### 값 타입 비교

- 값이 같으면 같은 것으로 간주
- 동일성 비교 : == (참조 비교)
- 동등성 비교 : equals() (값 비교)

### 값 타입 컬렉션

- 값 타입을 컬렉션으로 저장시 @ElementCollection 사용

```java
@Entity
public class Member {
    @Id @GeneratedValue
    private Long id;
    
    private String name;

    @ElementCollection
    @CollectionTable(name = "address", joinColumns = @JoinColumn(name = "member_id"))
    private List<Address> addresses = new ArrayList<>();
}
```

- 엔티티 삭제시 컬렉션도 함께 삭제
- 지연 로딩(Lazy Loading) 적용
- 값 변경 시 기존 데이터를 삭제하고 새로운 데이터를 삽입

제약 사항

- 값타입 → 식별자 개념 없기에 변경시 추적이 어려움
    - 변경 발생시, 주인 엔티티의 연관데이터 모두 삭제 + 값 타입 컬렉션에 있는 현재 값 모두 다시 저장
- 값 타입 컬렉션을 매핑하는 테이블 - 모든 컬럼을 묶어서 기본키를 구성해야함
    - null 입력X, 중복 저장X

대안

- 값 타입 컬렉션 대신 **일대다 관계 고려**
- 일대다 관계를 위한 엔티티 + 값 타입
- 영속성 전이(cascade) + 고아 객체 제거 기능 필수로 가진다고 볼 수 있음

### 정리

값 타입 → 정말 값 타입이라 판단될 때 사용

엔티티와 값 타입 혼동 하여 엔티티 ⇒ 값 타입으로 만들면 안됨

**식별자 필요 + 지속적 값 추적 + 변경 ⇒ 엔티티**
