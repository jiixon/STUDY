### 상속관계 매핑

- 관계형 데이터베이스는 상속관계X
- 슈퍼타입 서브타입 관계라는 모델링 기법이 객체 상속과 유사
- 객체의 상속과 구조와 DB의 슈퍼타입 서브타입 관계를 매핑

슈퍼타입 서브타입 논리 모델을 실제 물리 모델로 구현하는 방법

1. 각각 테이블로 변환 ⇒ 조인 전략
    1. 각 테이블을 생성하고 조회할 때 조인을 사용
2. 통합 테이블로 변환 ⇒ 단일 테이블 전략
    1. 테이블을 하나만 사용해서 통합(JPA에서는 단일 테이블 전략이라고 함)
3. 서브타입 테이블로 변환 ⇒ 구현 클래스마다 테이블 전략
    1. 서브 타입마다 하나의 테이블을 만듬(JPA에서는 구현 클래스마다 테이블 전략이라고 함)

### 주요 애노테이션

- `@Inheritance(strategy=InheritanceType.XXX)` : 상속관계 매핑 방법을 선택
    - `JOINED`: 조인 전략
    - `SINGLE_TABLE` : 단일 테이블 전략
    - `TABLE_PER_CLASS` : 구현 클래스마다 테이블 전략
- `@DiscriminatorColumn(name=“DTYPE”)`
    - 부모 클래스에서 자식 클래스를 구분하는 컬럼의 이름을 설정
- `@DiscriminatorValue(“XXX”)`
    - 자식 클래스를 식별하기 위해 부모의 DTYPE 컬럼에 저장될 값을 설정

### 조인 전략

![상속관계 매핑](/JPA/images/img7.png)

```java
@Entity
@Getter 
@Inheritance(strategy = InheritanceType.JOINED)
@DiscriminatorColumn
public abstract class Item {

    @Id @GeneratedValue
    @Column(name = "ITEM_ID")
    private Long id;

    private String name;
    private int price;
}
```

- 슈퍼타입 Item 엔티티
    - 객체화 되지 않도록 추상클래스로 선언
- `@Inheritance(strategy = InheritanceType.JOINED)` - 매핑 전략 조인 전략으로 지정
- `@DiscriminatorColumn` - 구분자 컬럼
    - 기본값 DYPE

```java
@Entity
@Getter
@DiscriminatorValue("AlbumJPA")
public class Album extends Item {

    private String artist;
}
```

- 서브타입 엔티티 클래스, 슈퍼타입 Item 클래스 상속 받음
- `@DiscriminatorValue` 로 구분자 컬럼의 값을 정함
    - 기본값은 엔티티 이름

장점

- 테이블이 정규화
- 외래키 참조 무결성 제약 조건을 활용 할 수 있음
- 저장 공간이 효율화

단점
- 조회시 조인이 필요 → 단일 테이블 전략에 비해 성능저하
    - 조회 쿼리 복잡, 저장시 INSERT 쿼리 2번 호출

⇒ 상속 관계 매핑 전략 중 데이터베이스 관점에서 가장 정규화된 깔끔하고 정석적인 전략

### 단일 테이블 전략

![상속관계 매핑](/JPA/images/img8.png)

- 코드는 위와 동일, `@Inheritance(strategy = InheritanceType.SINGLE_TABLE)` 만 설정

장점

- 조인이 필요 없기 때문에 일반적인 상황에서 조회 성능 빠름 + 조회 쿼리 단순

단점

- 자식 엔티티에 매핑한 컬럼 모두 null 허용해야함
- 테이블의 컬럼 길이가 커짐 → 상황에 따라 조회 성능이 오히려 느려질 수 있음

### 구현 클래스마다 테이블 전략

![상속관계 매핑](/JPA/images/img9.png)

- `@Inheritance(strategy = InheritanceType.TABLE_PER_CLASS)` 사용
- 추천X

장점

- 서브 타입을 구분해서 처리할 때 효과적
- not null 제약 조건 사용 가능

단점

- 여러 자식 테이블을 함께 조회할 때 성능 저하
    - 전체 조회 이므로 SQL에서 `UNION`을 사용해야함 ⇒ 성능 많이 느려짐
- 자식 테이블을 통합해서 쿼리하기 어려움

### @MappedSuperclass

![상속관계 매핑](/JPA/images/img10.png)

```java
@MappedSuperclass
@Getter
public abstract class BaseEntity {

    private String createdBy;
    private LocalDateTime createdAt;
    private LocalDateTime lastModifiedBy;
    private LocalDateTime lastModifiedAt;
}
```

- 상속 관계 매핑 아님
- 부모 클래스는 테이블과 매핑하지 않고 상속받는 자식 클래스에게 매핑 정보만 제공하고 싶을 때 사용
- `BaseEntity`에서 온 `ID`, `NAME`이라는 같은 컬럼이 존재하지만 `MEMBER`, `SELLER`는 서로 관련 없는 독립 테이블
- 엔티티가 아니기에 `em.find()` 조회 메서드나 JPQL에서 사용 불가
- 실무
    - 객체들이 주로 사용하는 공통 매핑 정보를 정의
    - ex. 등록일, 수정일, 등록자, 수정자
    - 실제 객체화 할 일이 없기에 추상 클래스로 만듦
