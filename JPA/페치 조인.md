## 페치 조인(fetch join)

- JPQL에서 성능 최적화를 위해 제공하는 기능
- 연관된 엔티티나 컬렉션을 SQL 한 번에 함께 조회하는 기능
- 페치 조인 ::= [ LEFT [OUTER] | INNER ] JOIN FETCH 조인경로

엔티티 페치 조인

- 회원을 조회하면서 연관된 팀도 함께 조회 (SQL 한 번에)
- SQL을 보면 회원 뿐만 아니라 팀(T.*)도 함께 SELECT
- JPQL
    - `SELECT m FROM Member m JOIN FETCH m.team`
- SQL
    - `SELECT M.*, T.* FROM MEMBER M INNER JOIN TEAM T ON M.TEAM_ID=T.ID`

예시

1. 상황

    ```java
    Team teamA = new Team();
    teamA.setName("teamA");
    em.persist(teamA);
    
    Team teamB = new Team();
    teamB.setName("teamB");
    em.persist(teamB);
    
    Member member1 = new Member();
    member1.setUsername("member1");
    member1.setTeam(teamA);
    em.persist(member1);
    
    Member member2 = new Member();
    member2.setUsername("member2");
    member2.setTeam(teamA);
    em.persist(member2);
    
    Member member3 = new Member();
    member3.setUsername("member3");
    member3.setTeam(teamB);
    em.persist(member3);
    
    em.flush();
    em.clear();
    
    //teamA - member1, member2
    //teamB - member3
    ```

2. 엔티티 조회 - 페치 조인X

    ```java
    
    String query = "select m from Member m";
    List<Member> result = em.createQuery(query, Member.class).getResultList();
    
    for (Member member : result) {
        System.out.println("member = " + member.getUsername() + ", " + member.getTeam().getName());
    }
    ```

    ```sql
    Hibernate: 
        select
            m 
        from
            Member m select
                member0_.id as id1_0_,
                member0_.age as age2_0_,
                member0_.TEAM_ID as team_id4_0_,
                member0_.username as username3_0_ 
            from
                Member member0_
    Hibernate: 
        select
            team0_.id as id1_3_0_,
            team0_.name as name2_3_0_ 
        from
            Team team0_ 
        where
            team0_.id=?
    member = member1, teamA // SQL 조회
    member = member2, teamA // 1차 캐시
    Hibernate: 
        select
            team0_.id as id1_3_0_,
            team0_.name as name2_3_0_ 
        from
            Team team0_ 
        where
            team0_.id=?
    member = member3, teamB // SQL 조회
    ```

    - 처음에 member을 가져옴, 이후 team은 프록시 객체였지만 출력 for문에서 `member.getTeam().getName()` 로 team도 select 쿼리
    - member1  → SQL 조회, member2 → 1차 캐시로 따로 쿼리 날리지 않음
    - member3는 teamB 이므로 다시 team select 쿼리 나감

   → N+1 문제 발생 : 엔티티 목록 조회(member) - 1번, 각각의 엔티티에 대해 조회(team) - N번

3. 엔티티 조회 - 페치 조인 사용

    ```java
    String jpql = "select m from Member m join fetch m.team";
    List<Member> members = em.createQuery(jpql, Member.class)
        .getResultList();
    
    for (Member member : members) {
        //페치 조인으로 회원과 팀을 함께 조회해서 지연 로딩X
        System.out.println("username = " + member.getUsername() + ", " +
                           "teamName = " + member.getTeam().name());
    }
    ```

    ```sql
    Hibernate: 
        select
            m 
        from
            Member m 
        join
            fetch m.team  select
                member0_.id as id1_0_0_,
                team1_.id as id1_3_1_,
                member0_.age as age2_0_0_,
                member0_.TEAM_ID as team_id4_0_0_,
                member0_.username as username3_0_0_,
                team1_.name as name2_3_1_ 
            from
                Member member0_ 
            inner join
                Team team1_ 
                    on member0_.TEAM_ID=team1_.id
    member = member1, teamA
    member = member2, teamA
    member = member3, teamB
    ```

    - 한번에 가져와서 조회 ⇒ 이후에 다른 select 쿼리 나가지 않고 바로 처리

### 컬렉션 페치 조인

- 일대다 관계, 컬렉션 페치 조인
- JPQL
    - `SELECT t FROM Team t **JOIN FETCH t.members WHERE** t.name = ‘팀A’`
- SQL
    - `SELECT T.*, **M.*** FROM TEAM T INNER JOIN MEMBER M ON T.ID=M.TEAM_ID WHERE T.NAME = ‘팀A’`
- 예시

    ```java
    String jpql = "select t from Team t join fetch t.members where t.name = '팀A'"
        List<Team> teams = em.createQuery(jpql, Team.class).getResultList();
    
    for(Team team : teams) {
        System.out.println("teamname = " + team.getName() + ", team = " + team);
        for (Member member : team.getMembers()) {
            //페치 조인으로 팀과 회원을 함께 조회해서 지연 로딩 발생 안함
            System.out.println(“-> username = " + member.getUsername()+ ", member = " + member);
    	}
    }
    ```

    ```sql
    teamname = 팀A, team = Team@0x100
    -> username = 회원1, member = Member@0x200
    -> username = 회원2, member = Member@0x300
    ```

    - 하이버네이트6부터 DISTINCT 명령어 사용하지 않아도 중복 제거가 자동으로 적용

### 페치 조인과 일반 조인의 차이

일반 조인

- 일반 조인 실행시 연관된 엔티티를 함께 조회하지 않음
- JPQL
    - `SELECT t FROM Team t JOIN t.members`
- SQL
    - `SELECT **T.*** FROM TEAM T INNER JOIN MEMBER M ON T.ID=M.TEAM_ID`
- JPQL은 SELECT 절에서 t만 선택했음 → JPA는 Team 엔티티만 영속성 컨텍스트에 넣고 Members는 버림
- 즉, 실제 SQL은 팀-멤버 둘다 조인해서 SELECT 하지만, JPA는 결과로 팀만 매핑하고 멤버는 무시
- 회원 조회하려면?
    - `team.getMembers()` 호출 시점에 지연로딩(LAZY) 발생
    - N+1 문제 발생 가능

페치 조인

- 페치 조인 실행 시 연관된 엔티티를 함께 조회
- JPQL
    - `SELECT t Team t **JOIN FETCH** t.members`
- SQL
    - `SELECT **T.*, M.*** FROM TEAM T INNER JOIN MEMBER M ON T.ID=M.TEAM_ID`
- JOIN FETCH는 조인 대상인 members를 함께 조회하라는 명령
- SQL은 동일하지만, JPA가 Teamr과 Member 둘다 엔티티로 영속성 컨텍스트에 등록
    - 한 번의 쿼리로 객체 그래프 전체를 로딩

### 페치 조인의 특징과 한계

- 페치 조인 대상에는 별칭을 줄 수 없음
    - 객체의 상태와 DB의 상태 일관성(데이터 정합성)이 깨질 가능성 있음
- 둘 이상의 컬렉션은 페치 조인 불가능
- 컬렉션을 페치 조인하면 페이징 API 사용 불가능
    - 일대다 페이징시, 팀A에 회원1, 회원2가 있다면 페이지 사이즈가 1일 경우 팀A에는 회원1만 들어있음 ⇒ 데이터 정합성 맞지 않음
- 연관된 엔티티들은 SQL 한번으로 조회 - 성능 최적화
- 엔티티에 직접 적용하는 글로벌 로딩 전략보다 우선함
    - 글로벌 로딩 전략 : `@OneToMany(fetch = FetchType.LAZY)`
- 최적화 필요한 곳 → 페치 조인 적용
