### 연관관계 매핑

- 객체와 관계형 데이터베이스 테이블의 매핑 방법
- 방향(Direction)
    - 단방향
        - 회원 → 팀 또는 팀 → 회원
        - 둘 중 한쪽만 참조하는 것
    - 양방향
        - 회원 → 팀  + 팀 → 회원
        - 양쪽 모두 서로 참조하는 것
    - 방향은 객체관계에서만 존재, 테이블 관계는 항상 양방향
- 다중성(Multiplicity)
    - 다대일(N:1) - @ManyToOne
    - 일대다(1:N) - @OneToMany
    - 일대일(1:1) - @OneToOne
    - 다대다(N:N) - @ManyToMany
- 연관관게의 주인(Owner)
    - 객체를 양방향 연관관계로 만들면 연관관계의 주인을 정해야 함

예제

- 회원과 팀이 있다.
- 회원은 하나의 팀에만 소속될 수 있다.
- 회원과 팀은 다대일 관계이다.

### 단방향 연관관계

![연관관계 매핑](/JPA/images/img5.png)

```java
@Entity
public class Member {
    @Id
    @Column(name = "MEMBER_ID")
    private String id;
    private String username;
    
    @ManyToOne
    @Joincolumn(name = "TEAM_ID")
    private Team team;
 }
 
 @Entity
 public class Team {
     @Id
     @Column(name = "TEAM_ID")
     private String id;
     private String name;
 }
```

1. 객체 연관관계
    1. 회원과 팀 객체는 단방향 관계
    2. 회원은 Member.team 필드를 통해 팀 알 수 있지만, 팀은 회원을 모름
2. 테이블 연관관계
    1. 회원 테이블은 TEAM_ID 외래키로 팀 테이블과 연관관계를 맺음
    2. 테이블 연관관계는 반드시 양방향 관계
3. 객체 연관관계와 테이블 연관관계의 차이
    1. 객체(참조를 통한 연관관계)
        1. 양방향으로 만들고 싶으면, 반대쪽에 필드 추가하여 참조를 보관
        2. 서로 다른 단방향 관계 2개
    2. 테이블
        1. 외래 키 하나로 양방향으로 조인 가능

### 양방향 연관관계

![연관관계 매핑](/JPA/images/img6.png)

```java
@Entity
public class Member {
    @Id
    @Column(name = "MEMBER_ID")
    private String id;
    private String username;
    
    @ManyToOne
    @Joincolumn(name = "TEAM_ID")
    private Team team;
 }
 
 @Entity
 public class Team {
     @Id
     @Column(name = "TEAM_ID")
     private String id;
     private String name;
     
     @OneToMany(mappedBy = "team")
		 private List<Member> members = new ArrayList<>();
 }
```

- 다대일(N:1)
    - 다(Member)
        - `@ManyToOne`
        - `@JoinColumn`
        - 외래키를 가짐
    - 일(Team)
        - `@OneToMany`
        - 연관관계 주인을 `mappedBy`로 지정


> 💡**일대다(1:N) 양방향 대부분 실무 사용X**
> 반대로 1(Team):N(Member)은 사용하지 않는다.
>
> ```java
> @Entity
> public class Team {
>     @OneToMany
>     @JoinColumn(name = "team_id")
>     private List<Member> members = new ArrayList<>();
> }
>
> @Entity
> public class Member {
>     private String name;
> }
> ```
>
> - 외래키는 항상 N쪽에 있어야 함 → `Member`테이블에 `team_id`가 있어야 함
> - 지금 `Team`테이블에서 FK를 지정하려 함 → 불가능
> - `team.getMembers().add(member);` `em.persist(team);`
> - 해당 코드 실행 시:
    >   - `INSERT INTO Team`, 그다음에
>   - `UPDATE Member SET team_id = ? WHERE id = ?`
> - 즉, Member 테이블의 team_id를 수정해야 하므로 **쿼리 2번** 나감



연관관계 주인
- 객체에는 양방향 연관관계가 없음
    - 서로 다른 단방향 연관관계 2개
- 테이블에서는 객체의 참조는 둘인데 외래키는 하나
    - 두 객체 연관관계 중 하나를 정해 테이블의 외래키를 관리 ⇒ 연관관계 주인(Owner)
    - 연관관계 주인만이 데이터베이스 연관관계와 매핑되고 외래 키를 관리(등록, 수정, 삭제)할 수 있음
    - 반면에 주인이 아닌 쪽은 읽기만 가능
    - 주인은 mappedBy 속성을 사용하지 않음
    - Member가 연관관계 주인이고, 외래키를 가지고 있음

**@ManyToOne**
- `optional`
    - false로 설정하면 연관된 엔티티가 항상 있어야 함(기본값 true)
- `fetch`
    - 글로벌 페치 전략을 설정
    - 기본값
        - `@ManyToOne=FetchType.EAGER`
        - `@OneToMany=FetchType.LAZY`
- `casecade`
    - 영속성 전이

**@JoinColumn**
- `name`
    - 매핑할 외래키 이름
    - 기본값 : 필드명 + _ + 참조하는 테이블의 기본키 컬럼명
- `referencedColumnName`
    - 외래키가 참조하는 대상 테이블의 컬럼명
    - 기본값 : 참조하는 테이블의 기본 키 컬럼명
- `foreignKey`(DDL)
    - 외래키 제약조건을 직접 지정
    - 테이블을 생성할 때만 사용
- `unique`, `nullable`, `insertable`, `updatable`, `columnDefinition`, `table`
    - `@Column` 속성과 같음
